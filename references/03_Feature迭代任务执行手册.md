# Feature 迭代任务执行手册

## 出题目标

在已有功能基础上扩展或增强，强调新旧功能协同。描述"用户希望现有功能再多做一件事"，让模型在不破坏原有逻辑的前提下平滑迭代。

题目读起来像对现有功能的改进诉求，而不是重新设计一个系统。

---

## 提示词质量标准

**必须包含：**
- 明确说明是在现有功能基础上扩展（"目前已经支持……希望新增……"）；现状锚点最多一句，只用于说明扩展对象。
- 新增能力的具体描述（做什么、针对什么场景）
- 对现有功能兼容性的隐含要求（旧功能不受影响）
- 两个以上相关能力点：新能力本身，加上它与既有列表、详情、统计、权限或历史记录中的至少一处联动。
- 至少一项非开心路径：空数据、失败重试、重复操作、极端输入或中途离开再回来。

**禁止包含：**
- 文件路径、类名、函数名、模块名
- 技术实现指令（"在 xxx 方法里加一个参数"）
- Markdown 格式

**隐藏约束：**
- 允许把"切换页面返回后仍保持原状态""历史记录同步显示新的类型"这类合理预期留在题面之外，交由验收阶段核对。
- 不允许隐藏扩展对象本身：在哪个已有能力上扩展、扩展后多出什么必须写进题面。

**字数要求：**
- 全文不超过 250 字（空白字符不计入），约束要求融入正文，不得单独分行或加标签前缀

---

## 正确示例

目前导出报表只支持 Excel 格式，希望增加 PDF 导出选项，用户导出时可以选择格式，两种格式的内容和布局保持一致。历史导出记录里要显示对应的格式类型，导出过程中生成失败时要给出失败原因并提供重试入口；原有的 Excel 导出入口和已有历史记录的展示保持不变。

---

## 反面示例（禁止出现此类写法）

❌ 在 ExportController 的 export() 方法中增加一个 format 参数，当 format="pdf" 时调用 PdfGenerator.generate()，否则走原有 ExcelExporter 逻辑。

❌ 修改 export_service.go，支持传入 type 参数。

---

## 常见错误

1. 没有体现"在现有功能上"扩展 → 补充"目前已支持……"的描述
2. 新功能和旧功能的关系模糊 → 说明新旧功能如何共存
3. 改动范围太大（像新建系统）→ 缩小到一个具体功能点
4. 超过 250 字 → 删去铺垫语，保留"现有情况 + 新需求 + 联动约束"核心
